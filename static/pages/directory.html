LDAP / Active Directory Connection

Read-only. SecLog binds and searches for computer objects on the schedule below -- it never connects to a discovered machine itself. To get the shipper onto one, use its enrollment token from the table below (same one-time-token flow as Agents).
SECLOG_MASTER_KEY is not set on the server -- a bind password can't be saved until an administrator sets it (see README: Directory sync).

Directory Login

Let people sign in with their domain username and password instead of a local SecLog account. Uses the same connection above to look the person up, then binds as them with the password they entered to verify it -- SecLog never sees or stores it. A local account with the same username always wins; the directory is only consulted when no local account exists yet.
The literal text {username} is replaced with whatever was typed on the login screen.
Members of this group (via memberOf) get the admin role on login. Leave blank and nobody signs in as admin through the directory.
Saved together with the connection settings above -- use the same Save button.

Deployment Packages

A headless install script for pushing the shipper to many machines at once via Group Policy (Computer Startup Script) or Intune (Platform Script), instead of copy-pasting the one-time install command onto every host by hand. Unlike the per-host token above, this one can enroll multiple machines within a use limit and expiry you choose. "OU" is a label for your own bookkeeping only -- SecLog can't verify a machine running the script is actually in that OU.
