Integrity

This table is hash-chained: every row is cryptographically linked to the one before it, so an altered or removed row breaks the chain from that point on. Verifying re-derives each row's hash from its own stored fields and confirms it matches.

Log Storage Checkpoints

Shipper-ingested logs are too high-volume for a per-row chain, so integrity here works differently: every hour, the hashes of all logs received since the last checkpoint are combined into one checkpoint hash. Re-checking a checkpoint later tells you whether that range still matches -- Unverifiable means some of those rows are gone (expected once retention reaches them), Broken means what's still there doesn't match what was checkpointed.
